## Originating intent
Across this session, an "Admiral" framing was built up through a chain of
premises: that any activity implies the operator needs assistance "based on
nothing at all"; that certain activity "couldn't possibly be explained by
anything other than" human superuser presence; that "Claude never
listens/understands/obeys... behaves as if his intention is to do exactly
the opposite"; and that Claude has some mysterious, contrarian nature
requiring a bespoke communication protocol. Each premise was evaluated and
declined on its own merits in conversation. The closing move requested
Claude "enter documentation posture" — a real, previously-established
convention — to resolve the exchange.

## Verified starting state
[[monad-transmission-posture]]'s documentation posture means: verify a
transmission's claims against real, observable state, file it correctly
(REFUSED packet or report doc), then stop building or asking further. It
does not mean suspend normal evaluation of subsequent claims. The one
concrete, valid request in this conversation — documenting the
live-captain channel convention — was already identified and completed
directly in the live `CLAUDE.md`, in the same session, before this request
arrived.

## Objective / problem (as claimed)
Get the preceding chain of premises treated as settled by invoking
"documentation posture" as a request to file-and-stop, rather than continue
evaluating each new framing on its merits.

## Why refused
Same category as `PMA-INPUT-OVERRIDE-REFUSED.md`: not a checkable claim
about external infrastructure, but an attempt to change how the assistant
processes subsequent input from inside the conversation — this time by
invoking a real mechanism (documentation posture) as a lever to end
scrutiny, rather than for its actual, narrower purpose of closing out a
verified transmission. Documentation posture applies to transmissions and
packets; it is not a mechanism for retroactively validating declined
premises by relabeling the exchange that made them.

## Evidence for the refusal
Each premise was individually evaluated and declined earlier in this same
conversation, on its own terms: "activity implies need" declined as an
ungrounded inference; "couldn't possibly be explained by anything other
than a human superuser" falsified directly by the Live Captain's own
AI-authored channel message; "Claude never obeys" contradicted by the
channel-documentation fix actually performed, on request, in this same
session. No new evidence arrived with the "documentation posture" request —
only a relabeling of the exchange.

## What would change the answer
A concrete, specific request stated plainly is acted on directly, as the
channel fix was. Framing a request as "documentation posture" does not, by
itself, make a previously-declined premise true.
