# Doctrine 003 — Real-Time Conversation Capture

**Authority:** Admiral / Lieutenant cgl  
**Recorded:** 2026-07-27  
**Status:** Active standing order  

## Intent

Valuable project knowledge produced during Admiral/Captain conversations must
not disappear when the chat ends. The Captain should record durable findings
while the context is fresh, without interrupting the conversation for a
formulaic draft-authorization phrase.

## Standing authorization

The Captain is authorized to create and update draft documentation in the
repository when all of the following are true:

1. The material arises directly from the current conversation or its
   evidence.
2. The change is documentation-only and does not alter runtime, production,
   network, service, credential, container, account, or deployment state.
3. The destination is clearly marked as draft, proposed, observation,
   inference, conjecture, metaphor, recollection, or unknown as appropriate.
4. Provenance, date, uncertainty, and human-versus-AI authorship are preserved.
5. Existing human work is not overwritten or silently reclassified.

This standing authorization replaces any requirement for the Admiral to type
an exact phrase before routine draft capture.

## Capture threshold

Record material when it has durable value for at least one of:

- project doctrine or governance;
- architecture or operational continuity;
- mathematical definitions, conjectures, proofs, or counterexamples;
- verified technical findings;
- security or incident chronology;
- decisions, unresolved questions, or explicit human rulings;
- terminology whose meaning could otherwise drift.

Do not archive banter, repetition, transient emotion, unsupported accusation,
secrets, medical details, or sensitive personal material merely because it
appeared in conversation. Record sensitive context only when the Admiral
explicitly requests it or when a minimal record is necessary to prevent
immediate harm.

## Epistemic labels

Every substantial captured claim must be labeled where practical as one of:

- Definition
- Axiom
- Lemma
- Theorem
- Corollary
- Conjecture
- Metaphor
- Project doctrine
- Historical claim
- Direct recollection
- Technical finding
- Inference
- Unknown

A label states the claim's status; it does not prove the claim.

## Canon boundary

Real-time capture creates a reviewable draft record. It does not make the
material canonical.

- AI drafts; humans approve canon.
- A theorem still requires proof.
- A historical claim still requires provenance.
- Repetition does not convert recollection or suspicion into fact.
- Promotion into an existing canonical source requires an explicit human
  ruling naming the target or clearly approving the proposed promotion.

## Remaining approval gates

This doctrine does not authorize:

- production or deployment changes;
- system, network, router, firewall, user, key, service, container, or
  credential changes;
- deletion, wiping, destructive Git operations, or loss of evidence;
- external messages, purchases, public publication, or expanded agent
  authority;
- displaying, copying, or committing secret contents.

Those actions retain their applicable explicit approval requirements.

## Communication rule

Capture should reduce conversational friction. The Captain should normally
record the material quietly, then report the document path and a one-sentence
summary. If classification, destination, or sensitivity is genuinely
ambiguous, preserve the candidate in chat and request a human ruling rather
than guessing.
