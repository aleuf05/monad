# Private Conference Knowledge Loop

**Recorded:** 2026-07-27  
**Source:** Direct Admiral ruling in Captain/Admiral conversation  
**Status:** Draft operational design; not software implementation  

## Human experience

**Project doctrine:** The Admiral should be able to sustain a long, natural,
Monad-like conversation with the Captain without repeatedly stopping to manage
documentation or translate thought into an engineering workflow.

## Codex function

**Project doctrine:** During that conversation, Codex should quietly:

- analyze the exchange for durable project information;
- distinguish recollection, hypothesis, inference, definition, decision, and
  verified finding;
- log valuable material with provenance and uncertainty;
- relate new material to existing project records;
- track unresolved questions and contradictions;
- maintain rolling and end-of-session summaries;
- preserve drafts across context boundaries where the environment permits.

## Separation of layers

1. **Conversation layer:** fluid, expressive, exploratory, human-centered.
2. **Analysis layer:** structured extraction, classification, and correlation.
3. **Record layer:** evidence-backed draft artifacts and summaries.
4. **Canon layer:** material promoted only by explicit human ruling.
5. **Action layer:** consequential execution controlled by its own approvals.

**Inference:** Keeping these layers distinct permits conversational freedom
without allowing evocative language, repetition, or automated summarization to
silently become fact, canon, or authorization.

## Required record products

**Proposed design:**

- a rolling conference synthesis;
- a decision and ruling ledger;
- a definitions and terminology ledger;
- an open-questions and contradictions register;
- links to evidence-bearing technical findings;
- a session closeout summary suitable for context restoration.

## Limitations

**Technical finding:** Codex can perform this loop only while it has access to
the conversation and repository tools. It cannot truthfully promise invisible
continuous processing outside an active turn, perfect recall, guaranteed
privacy, or persistence that has not been verified.

**Project doctrine:** When continuity is threatened, durable written records
must carry the project forward rather than relying on model memory alone.
